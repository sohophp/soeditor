# WYSIWYG + Source 主线与按需加载实施规划

## 状态与决策

2026-09-05：WS1–WS6 本地实施与适用自动验收完成，包含首次 Source 加载、失败恢复、增强按需加载、编辑／分屏回归、独立基线与最终测量、打包消费者和 Winstar 集成。真实 Safari 与辅助技术人工验收、版本发布及生产部署不属于本轮完成声明。详见[实施证据](wysiwyg-source-evidence.zh-CN.md)。

SoEditor 优先完成网站 CMS 的 WYSIWYG + HTML Source 编辑能力。Source 是主线能力，宿主可以选择不显示；默认打开 WYSIWYG 时，不因配置了 Source 按钮就提前下载或初始化源码编辑器。其它已有功能保留独立入口，默认不加载，不在本轮删除或扩展。

产品约束依次服从 `AGENTS.md`、[PRODUCT](PRODUCT.md)、[ROADMAP](ROADMAP.md)、[编辑规范](wysiwyg-editor.md)。历史阶段的完成记录不能替代本轮验收。

## 改造前代码事实（规划基线）

以下是规划制定时的源码快照；最新测量和进展见实施证据，不能将此列表作为当前完成状态。

- `packages/soeditor/src/cms.ts`：窄 CMS 入口，拒绝 Source、Preview 和 save 配置，提示使用 `cms/optional`。
- `packages/soeditor/src/cms-optional.ts`：已有显式可选入口，可以作为兼容迁移基础。
- `packages/soeditor/src/classic-editor.ts`：配置包含 Source 时，在创建阶段动态导入 Source 和 HTML Tools；尚未达到首次激活才加载。
- `packages/soeditor/src/index.ts`：保留多个历史功能的广泛导出，需要检验实际消费者构建图，不能把根入口等同于轻量入口。
- `packages/soeditor/vite.config.ts`、`vite.cms.config.ts`、`vite.global.config.ts`：ESM、CMS 和全局构建边界不同，必须分别验收。
- `packages/source/src/classic-source-enhancements.ts`：已有选择、滚动同步与格式化挂接逻辑；延迟初始化时需要维护其生命周期。
- Classic 已有左右和上下 WYSIWYG/Source 视图；保留这一用途，不恢复通用开发工作区。

## 模式、视图与产品功能的区别

对外只把 WYSIWYG 和 HTML Source 称为主线编辑模式。左右／上下分屏是这两个编辑模式的显示方式，Preview 是只读预览，不能当作第三个内容写入端。

现有 Developer Visual、Inspector、Outline、Problems、命令面板和通用 Workspace 属于开发／兼容能力；Markdown 是另一种内容编辑能力；批注、修订和审阅属于工作流。这些能力保留独立包与已有接入方式，但不出现在普通 CMS 默认工具栏、初始依赖图或预加载中。这里的“开发模式”也不同于 Vite 开发服务器或生产构建选项。

“更轻”的验收分为三项：首次下载与解析减少、初始化和实例内存减少、重复编辑操作不退化。仅隐藏按钮不会减少已打包代码；按需加载会把部分成本移到第一次使用，不能保证完整使用后的累计下载更小，也不会自动缩小安装包。

## 能力与加载矩阵

| 能力                                                     | 产品定位         | 目标加载时机                     |
| -------------------------------------------------------- | ---------------- | -------------------------------- |
| WYSIWYG 核心、历史、HTML 数据层                          | 默认主线         | 编辑器初始化                     |
| 段落、列表、链接、图片、表格、粘贴、表单                 | 默认主线         | 必要命令随主线；昂贵 UI 可按需   |
| HTML Source、语法编辑和查找                              | 主线，可选择暴露 | 第一次进入 Source 或源码分屏     |
| 左右／上下源码分屏                                       | 主线             | 请求分屏时，复用 Source 加载     |
| 格式化、压缩、高级诊断                                   | 可选增强         | 明确调用时；自动格式化须显式启用 |
| Preview 及其模板                                         | 保留可选能力     | 明确调用时                       |
| SoFinder、上传和自定义保存适配器                         | 宿主集成         | 宿主显式导入并按自身流程启用     |
| Developer Visual、Inspector、Outline、Problems、命令面板 | 保留兼容能力     | 独立入口；CMS 不加载             |
| Markdown、批注、修订、审阅、通用布局                     | 保留兼容能力     | 独立入口；CMS 不加载             |
| React/Vue 包、插件开发工具、Playground                   | 适配或开发用途   | 由相应消费者显式使用             |

资源隔离包括 JavaScript、CSS、语言包、worker、预加载和模块顶层副作用。保留包可能继续占用安装或发布空间；浏览器首屏成本与安装包大小必须分开报告。

## WS1 — 建立可复现基线

工作：

- 保留现有工作区改动，记录提交、工作区差异、运行环境、构建参数和产物来源。
- 从实际 CMS ESM、全局包及打包后消费者追踪依赖；同时记录构建模块图与浏览器请求，不能仅搜索功能名称。
- 记录 WYSIWYG 首次可编辑时间、首次 Source 切换、再次切换、输入、粘贴、表格操作、内存与销毁。
- 使用 10 KiB、100 KiB、500 KiB 的真实结构 HTML，覆盖图片、表格、未知元素和 CMS 标记；冷缓存与热缓存分别记录。
- 核对执行脚本、路线图及发布文档中的预算差异，明确字节单位和权威门禁；不得取较宽松数值自动通过。

交付：带来源的基线报告、依赖图、排除模块清单和测量脚本。分别记录初始传输 raw/gzip/CSS、Source 增量与累计、格式化增量、全功能历史产物。WS1 未完成前不承诺减少百分比。

验收：同一环境可复测；默认 WYSIWYG 与启用 Source 但未打开的场景有独立证据；缺失环境或测试明确列出。

## WS2 — 收窄入口与资源依赖

工作：

- 保持已发布的 `cms`、`cms/optional` 和根入口可用；先在可选 CMS 路径实现延迟 Source，不把入口重命名作为前置条件。
- 文档与普通 CMS 示例使用窄入口；开发示例归入明确标注的兼容示例。
- 拆分会带入可选功能的桶导出、公共 CSS、语言资源和初始化副作用；只导入实际需要的运行时符号。
- 限定 layout、projections、workspace 的内部必需部分，避免为分屏或表单生命周期引入通用工作区。
- 给 ESM 和全局分发分别定义支持矩阵。当前全局包不支持的 Source 不应被文档承诺；需要支持时采用独立可选产物及显式加载契约，主全局包保持轻量。

交付：入口与资源边界改造、迁移说明、打包后消费者检查。是否最终合并 CMS 接入方式留到兼容性评估后决定，不预先发布新 API 名称。

验收：默认构建及初始网络请求均无禁止模块及其资源；原有独立功能入口仍可使用；没有意外改变公共导出。

## WS3 — Source 首次激活与生命周期

工作：

- 建立未加载、加载中、就绪、失败、已销毁状态；由 Source 按钮、初始 Source 和两种分屏共享加载流程。
- WYSIWYG 默认启动不请求源码模块；初始 Source 作为明确激活直接等待其加载。
- 显示可访问的加载状态，失败提供重试；加载期间保留可用的 WYSIWYG 和最新内容。
- 快速切换只执行最新视图意图，复用同一加载任务；模块可以跨实例缓存，实例状态和 DOM 不共享。
- 加载期间发生 setData、readonly、form reset、销毁时，以当前实例状态为准，防止旧异步结果覆盖新内容或重新挂载。
- 后续切换复用已创建的 Source 实例；插件、命令、服务的延迟注册必须符合现有生命周期，不绕过事务与历史。

验收：Source 按钮可见但未点击时零 Source 请求；首次打开才加载；重复打开不重复初始化。覆盖失败重试、快速切换、多个实例、销毁竞态和初始 Source。

## WS4 — 分离 Source 增强与其它可选功能

工作：

- Source 基础编辑不依赖完整 HTML Tools 入口；基础安全投影校验与可选高级诊断分开。
- 格式化／压缩操作首次调用再加载所需实现；自动格式化只在显式配置且 Source 已激活后启动。
- 预览实现及模板在请求预览时加载；保存适配器由明确配置决定，不改变普通表单同步。
- 检查 UI 禁用、加载错误和异步格式化竞态，旧格式化结果不得覆盖较新的输入。

验收：Source 打开后不自动请求 Prettier、开发工具或 Preview；每项增强只有在触发后产生自身资源请求；错误不会丢失内容或破坏撤销。

## WS5 — 完整编辑与分屏回归

工作：

- 确保 canonical HTML、Source 草稿和 WYSIWYG 投影的职责清楚，切换不产生非用户修改和多余撤销步骤。
- 无法安全投影的 Source 保留草稿，维持最后有效的惰性视图并说明状态；保存、提交与切换不得悄悄输出旧 HTML，向宿主明确报告阻止提交的状态。
- 检查未知标签、属性、业务 class/style、注释、CMS 标记、表格和嵌套结构的语义往返；编辑器临时 class 和状态不得写入内容。
- 左右与上下分屏保留可拖动尺寸和键盘替代；只有一个活动写入端，选择及可选滚动同步不抢焦点、不形成循环。
- 覆盖普通编辑、中文 IME、粘贴、链接、图片、表格拖动和属性、undo/redo、readonly、表单 submit/reset、多实例和销毁。

验收：完整浏览器操作链同时检查可见结果和 getData；单元测试不能替代实际编辑器操作。Chromium、Firefox、WebKit 分别报告，真实 Safari 与辅助技术人工结果另记。

## WS6 — 实测优化、分发与宿主验证

工作：

- 对比 WS1：分别报告首屏、首次 Source、再次切换、格式化以及累计完整使用成本；不能只把成本移到另一个包就称为总体减小。
- 按实测热点优化 HTML 解析、工具栏状态更新、重复监听、UI 挂载和共享代码；不以牺牲 HTML 保真换体积。
- 验证 ESM、CMS 全局包、可选产物、CSS 路径、CSP/资源部署限制及打包安装后的真实消费者。
- 在 Winstar 接入前核对其现有入口、表单和 SoFinder 契约，先准备可审查的集成变更及回退路径；本规划不包含生产部署。
- 更新配置、API、分发、资格与发布决策文档，标记实际完成状态，不覆盖历史证据。

验收：适用的 lint、类型、单元、文档、API、消费者、分发、体积及浏览器检查通过。沿用经核对的现有门禁，不放宽失败预算；新增 Source 延迟和增量预算以 WS1 数据提出并审核。人工验证缺项不得标记为全量发布通过。

开发投入先保障正文编辑、Source 保真与保存安全，再优化首屏和首次使用反馈。兼容能力只处理安全、兼容和严重缺陷；不为“功能保留”持续扩充默认主线。各里程碑按验收结果推进，不用预估工期替代完成条件。

## 兼容迁移与回退

- 普通 CMS 使用窄 CMS 入口；需要 Source、Preview 或保存适配器时使用现有 `cms/optional`。样式使用对应 CMS 样式入口，根入口继续兼容。
- 调用可能首次加载 Source 的视图切换时，宿主应等待返回结果后再依赖 Source DOM；就绪后的切换继续复用实例。
- 发布与部署必须保留构建器生成的可选 chunk、恢复资源和资源目录关系；在带部署前缀的真实消费者中检查 URL 与 CSP。
- Winstar 回退使用同一版本的依赖、锁文件、适配器、CSS、manifest 和完整构建产物；不能只回退入口 JS，留下不匹配的资源哈希。原生 textarea 内容与表单契约保持可用。
- 不在本轮合并或重命名已发布入口，不删除兼容包，不进行版本发布或生产部署。若未来需要破坏性调整，另行记录迁移与 SemVer 决策。

## 实施顺序、风险与边界

按 WS1 → WS2 → WS3 → WS4 → WS5 → WS6 推进；每阶段提交可审查的改动与证据，前一阶段失败不靠后续文档状态掩盖。每个运行时代码阶段即运行相关回归，WS5 再做完整交互验收。

主要风险是延迟插件注册、共享导出误带依赖、CSS/预加载绕过隔离、异步视图和格式化覆盖内容、不同分发格式行为不一致。对应措施分别是生命周期测试、模块图和网络双检、资源清单、竞态测试和打包后消费者验证。

本轮不删除兼容包、不扩展其它产品线、不提高预算、不改持久化 HTML 契约、不发布版本或部署生产。优先让默认 WYSIWYG 更轻，同时保证 Source 完整可用，首次打开的等待成本可见、可测、可恢复。
