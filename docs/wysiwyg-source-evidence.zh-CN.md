# WYSIWYG + Source 实施证据

## WS1 基线

使用 `node scripts/measure-cms-loading.mjs /tmp/soeditor-cms-loading.json` 构建独立生产模式消费者，读取构建模块图并运行 Chromium。首次创建与同页面销毁后再次创建分别测量。脚本使用 10 KiB、100 KiB、500 KiB 的段落、标题、链接、表格、注释及未知 CMS 元素组合。

[原始基线](evidence/wysiwyg-source-baseline.json)记录时间、提交、工作区状态、Node 版本、各 chunk 模块与静态／动态依赖、网络请求、创建／切换／格式化／销毁时长和堆使用量。它来自本轮修改运行时代码之前的构建，不能作为最终构建成绩。工作区补丁及构建日志保存在本机 `/tmp/soeditor-ws-baseline/`，不是已提交的发布证明。

| 产物             | raw 字节 | gzip 字节 |
| ---------------- | -------: | --------: |
| CMS 全局 JS      |   486672 |    149968 |
| 独立 CMS CSS     |    26778 |      4896 |
| CMS ESM 入口文件 |      189 |       156 |

ESM 入口文件大小不代表完整加载成本，必须沿其依赖图计算。独立消费者中，未启用 Source 时首次请求为 HTML、JS、CSS 共三项；启用 Source 后增加两个 JS 请求，首次点击 Source 已无新请求，证实当前基线为初始化加载。

这些是单次实验数据，不是统计分位数或正式延迟预算。堆数据也不能单独证明没有泄漏。输入、粘贴、表格、多次生命周期的隔离补测及跨浏览器结果见后文。

## 测量口径

- `create` 从页面入口已加载后调用创建 API 开始，到创建 Promise 完成为止；不包含导航和主 JS 下载，不能称为整页首次可交互时间。冷实例使用新浏览器上下文；热实例在同页面销毁后重建。
- Source 首次／再次切换计时等待视图切换 API；首次包含相应动态加载。格式化计时包含首次实现加载与格式化工作。
- 输入从原生 `beforeinput` 到下一动画帧；粘贴使用带文字、图片 HTML 的合成 ClipboardEvent；表格使用实际点击选中后执行插入行命令到下一帧。它们不是操作系统剪贴板、人工 IME 或辅助技术认证。
- 每个文档／Source 配置组合有三个额外创建／Source 激活／销毁循环，记录显式 GC 后堆数据并断言编辑器 DOM 清空。单轮堆差值不能证明不存在所有监听器或浏览器内部泄漏。
- 原始测量没有完整输入／粘贴／表格时延，因此另外用保存的提交、工作区补丁及原有未跟踪源码重建隔离基线。其全局 JS、CSS、CMS ESM 的 raw/gzip 均与原始记录逐项匹配后才使用补测结果。

## 预算核对

初始执行脚本 `scripts/verify-release.mjs` 使用全局 raw 510000 字节、gzip 150000 字节、CSS 27250 字节；历史 ROADMAP 更严格地写为 500 kB、150 kB、27 kB。本轮已统一执行较严格门禁：500000 / 150000 / 27000 字节（十进制 kB），未放宽预算。

## 新增加载门禁

`scripts/cms-loading-budgets.mjs` 与 `pnpm test:loading` 同时检查构建模块图和实际请求，CI 在完整测试后执行。所有体积均为字节，gzip 使用脚本实际压缩结果，不等同于 HTTP 响应头统计。

| 项目                                   | raw 上限 | gzip 上限 | 依据                                                   |
| -------------------------------------- | -------: | --------: | ------------------------------------------------------ |
| 配置 Source 但未打开的初始 JS 请求总和 |   514018 |    152376 | 不超过 WS1 的消费者初始主 JS                           |
| 首次 Source 新增 JS 请求总和           |   600000 |    210000 | WS1 源码 chunk 589229 / 203176；单列首次使用预算       |
| 首次格式化新增 JS 请求总和             |   650000 |    160000 | WS1 格式化 chunk 641555 / 152808；与 Source 分开       |
| 仅失败后使用的恢复资源                 |   800000 |    260000 | 新增故障恢复副本；禁止首屏请求，单列安装与异常路径成本 |

Source 延迟门禁在同一 localhost 生产消费者上执行：10／100／500 KiB 首次分别不超过 1000／2000／5000 ms，再次分别不超过 300／1000／3000 ms。首次预算参考 WS1 的“启用 Source 创建 + 首次切换”总时长 447／953／3256 ms，容纳首次下载与初始化转移；不能拿原先已预加载的切换时长直接当作同一测量。它们是可复现环境中的回归上限，不是移动网络 SLA 或统计 P95。若 CI 环境差异导致失败，应先核对环境和重复测量，不自动放宽。

这些新增可选资源门禁不修改既有 CMS 全局、CSS 或普通交互预算。默认请求图必须排除 CodeMirror、HTML Tools、Preview、Developer Tools、Markdown、批注、修订及通用 Workspace；Source 的轻量恢复 URL 加载器可以随入口存在，但其运行时资源不能预加载。

首次 Source 比已预加载的旧切换更慢，这是延后下载与初始化的直接成本；界面提供加载反馈和失败重试。500 KiB 的创建和编辑仍有明显等待，不能称为所有大小文档都即时响应。专用 Classic host 移除了默认编辑事务中的通用 Workspace 恢复处理；本次输入／粘贴／表格样本下降，但不据单次样本承诺稳定改善比例。

六种配置各执行三个额外生命周期循环，销毁后编辑器 DOM 均为零。Source 开启场景三次 GC 堆读数约为 6.38→6.49→6.62 MiB（10 KiB）、6.51→6.61→6.75 MiB（100 KiB）、6.92→7.03→7.16 MiB（500 KiB）。夹具仍持有最后一个已销毁实例，且堆有少量增长；这些结果只支持有限循环下的观察，不能宣称零泄漏。既有独立内存保留门禁通过。

### 自动化与兼容性

- `pnpm test` 全链通过：单元、集成性能、API、文档、打包消费者、分发、发布体积检查、115 项产品 Chromium 测试和 6 项桌面／移动 CMS 测试。
- 完整兼容 Chromium 套件 **233 项通过**，覆盖保留的 Markdown、审阅、开发及通用工作区入口。旧大文档测试已等待 Source 就绪后调用格式化，原响应阈值未放宽。
- Firefox／WebKit 完整 WYSIWYG／CMS 回归 **96 项通过、4 项按既定 Chromium 专属范围跳过**；Source 专项三浏览器 **21 项通过**。
- Source 专项覆盖重复网络失败后的恢复、快速切换、最新内容／readonly、销毁竞态、无效草稿阻止原生表单及保存适配器、分屏滚动和 Preview 窗口复用。自动格式化测试同时验证只切换视图不改写内容，以及加载期间真实编辑的补偿。
- 原生选择发生在 Source 加载期间时，挂载后从当前选择补做定位，不抢焦点。
- `pnpm lint`、全工作区类型检查通过；`pnpm build` 已由完整测试链执行。API 报告与 24 个包的入口一致，文档清单含 233 项情景。
- 打包 Vite CMS 消费者 **436653 raw / 141517 gzip 字节**。打包 Source 消费者及独立生产测量均在 `script-src 'self'` 下验证正常模块失败、首次恢复失败、再次恢复成功。
- Source 恢复包包含隐藏源码映射及实际打包依赖的许可文件；不会因失败缓存而依赖刷新整个编辑页面，也不需要用 eval 或脚本 blob 来加载恢复模块。

构建和宿主 Vite 使用 Node 22.14.0。主机 Firefox／WebKit 运行库不足，跨浏览器使用 Podman 的官方 Playwright 1.62.1 Noble 镜像；其测试 runner 为 Node 24.18.1，页面服务仍由主机 Node 22 提供。结果属于自动化浏览器证据，不能代替真实 Safari 或屏幕阅读器人工认证。

### Winstar 集成与回退

- 适配器只切换到 CMS CSS 入口，保留原有表单、内部链接、SoFinder 图片／文件边界、上传与生命周期契约。
- Vite 为作为静态资源输出的 JS 增加内容哈希，避免恢复副本使用固定文件名。构建中的恢复文件与当前 Source runtime 逐字节一致。
- Winstar `pnpm tsc:check`、最终 `pnpm build` 和 **6 项浏览器集成测试通过**，`resources/dist` 已重建。
- 回退必须同步依赖、锁文件、适配器、Vite 资源规则及完整 dist／manifest；详见 Winstar 的 `docs/development/soeditor-integration.zh-CN.md`。原有无关未提交更改保持保留。

本轮未发布、打标签或部署生产。真实 Safari、辅助技术人工验收及发布决定仍单独保留，不以自动化通过替代。
