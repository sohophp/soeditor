# Phase 34 — 1.0 Public API Stabilization

## Status

COMPLETE.

## Goal

Classify, simplify, and freeze the evidence-backed public platform before 1.0
qualification, without publishing packages or promising untested runtimes.

## Required implementation

1. Inventory every package-root and declared subpath export as stable,
   experimental, deprecated, or internal.
2. Add a deterministic API report that detects symbol and declaration changes
   in CI.
3. Define SemVer, deprecation, browser/Node/framework support, security, and
   maintenance policy.
4. Preserve and compile representative 0.9 NodeNext, ESM, Vite, React, Vue,
   plugin, CMS, and browser integrations through public roots only.
5. Run all repository gates and an adversarial public-boundary review.

## Explicitly deferred

- package version `1.0.0`, npm publication, tags, hosted releases, or CDN
  verification;
- claiming Firefox/Safari or assistive-technology qualification without the
  required environment evidence;
- stabilizing APIs currently marked experimental merely to reduce the report;
- new product features, framework adapters, collaboration, or remote plugins.
