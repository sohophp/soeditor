# Phase 22 — SoEditor 0.6 Release Hardening

## Status

COMPLETE.

## Goal

Produce a coherent, owner-reviewable SoEditor `0.6.0` Developer Preview
candidate without performing an unauthorized npm publication, tag, or hosted
release.

## Sources of truth

- `AGENTS.md`
- `docs/PRODUCT.md`
- `docs/architecture.md`
- `docs/ROADMAP.md`
- `docs/DEVELOPMENT-POLICY.md`
- accepted ADRs, especially 0019–0023
- completed Phase 17–21 prompts and implementation

## Required implementation

1. Align the workspace and all 17 public package manifests at `0.6.0`, refresh
   the lockfile, and make release/registry tooling accept the 0.6 line while
   retaining explicit 17-package and scoped-name guards.
2. Add a 0.6 changelog entry and finalize migration, status, README,
   architecture, distribution, release-operation, package-count, and exact
   version language. Distinguish a verified local candidate from a published
   public release.
3. Audit every public export map, declaration/declaration map, JavaScript source
   map, stylesheet, license, repository field, peer dependency, and packed
   manifest. No wildcard, source, internal, or `workspace:` publication target
   may escape.
4. Exercise strict packed NodeNext, native Node ESM, normal Vite, and narrow
   Vite consumers at `0.6.0`. Preserve the narrow unused-feature and CSS
   assertions introduced in Phase 21.
5. Exercise Classic, Developer, Markdown, CMS/SoFinder, manual/debounced
   diagnostics, persistent projections, all split pairs, security, readonly,
   invalid-source, keyboard, accessibility, teardown, and repeated lifecycle
   behavior in real Chromium.
6. Measure and enforce the CDN global, standalone CSS, umbrella ESM, Playground,
   and narrow consumer budgets. Review dependency advisories and existing
   lifecycle/performance/leak evidence; document bounded limitations rather
   than claiming guarantees not measured.
7. Run from a frozen dependency graph: lint, strict typecheck, unit tests,
   packed consumers, distribution audit, release audit, Chromium, build,
   license verification, high-severity dependency audit, npm publication dry
   run, and the read-only registry availability preflight.
8. Perform a final read-only adversarial review. Fix every Critical and High
   finding and record accepted Medium/Low limitations in `docs/status.md`.

## Release boundary

The following remain owner-controlled and are not authorized by this phase:

- `pnpm release:publish`;
- creating or pushing a `v0.6.0` tag;
- creating a GitHub Release;
- changing license, npm identity, organization, token, or protected-environment
  policy;
- claiming registry or jsDelivr availability before external verification.

The public registry/CDN verification command is prepared for 0.6 but can only
pass after an authorized publication.

## Explicitly deferred

- new editor features or rule families;
- framework adapters, collaboration, advanced widgets, arbitrary docking, and
  persisted workspaces;
- 0.7–1.0 roadmap choices, except documenting evidence for the next deliberate
  roadmap decision.

## Definition of Done

- all 17 candidate packages are aligned at `0.6.0` with coherent documentation
  and a complete dry-run artifact set;
- frozen-install and every local release gate pass;
- the read-only registry preflight confirms `0.6.0` is not partially occupied;
- Critical = 0 and High = 0;
- the reviewed commit is pushed, while actual publication/tag/release remains
  explicitly pending owner authorization.
