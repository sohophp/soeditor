# Phase 29 — SoEditor 0.8 Review Workflow Release

## Status

COMPLETE.

## Goal

Produce a coherent, owner-reviewable SoEditor `0.8.0` review-workflow
candidate without performing an unauthorized npm publication, tag, or hosted
release.

## Required implementation

1. Publishable `@soeditor/comments` and `@soeditor/revisions` package roots
   with curated SDK and umbrella exports; no private-subpath dependency.
2. Explicit host-owned data contracts: immutable portable export, distinction
   between comment tombstoning and permanent erasure, optional permanent
   revision erasure, and permission checks for every governance operation.
3. A packed NodeNext/native ESM storage-adapter consumer that proves comment
   and revision export/erasure through public SDK contracts.
4. A 0.7-to-0.8 migration guide plus synchronized security, privacy,
   accessibility, lifecycle, release, API, architecture, and status docs.
5. Align all 19 public packages at `0.8.0`; update package-count, registry,
   license, artifact, bundle, and unpublished-version guards.
6. Run lint, strict typecheck, all tests/builds, license/security checks, npm
   dry run, and the read-only registry preflight.
7. Complete an adversarial review with Critical 0 and High 0, recording all
   accepted limitations.

## Data boundary

SoEditor does not become the database, identity provider, policy authority,
retention scheduler, or audit log. Export helpers return the bounded data
currently visible to one editor instance. Erasure succeeds only after the host
adapter confirms persistence; backend backups, replicas, legal holds, and
audit-retention rules remain host responsibilities.

## Release boundary

This phase does not authorize `pnpm release:publish`, npm publication, a
`v0.8.0` tag, a GitHub Release, or claims of public registry/CDN availability.

## Definition of Done

- all 19 public packages are aligned at `0.8.0`;
- packed public consumers prove review storage, export, erasure, security,
  accessibility, and terminal lifecycle behavior;
- every release gate and read-only registry preflight passes;
- Critical = 0 and High = 0;
- the exact reviewed commit is pushed, with publication still owner-controlled.
