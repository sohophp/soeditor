# Phase 16 Implementation Specification — 0.5.x Publication and Stabilization

## Status

Active implementation specification for Phase 16 of `docs/ROADMAP.md`.

## Goal

Prepare the completed SoEditor 0.5 codebase for a reproducible public npm/CDN
release and establish maintainable 0.5.x quality controls.

## Package and publication contract

All 15 public packages remain ESM at aligned version 0.5.0 for the initial
publication. Add canonical GitHub repository, package-directory, homepage,
issues, supported Node, public registry, and provenance metadata. Continue to
publish only explicit `dist` artifacts plus npm-standard README/package files.

Add a deterministic publish audit that examines packed manifests, rejects
workspace protocols or private paths in tarballs, and validates dry-run
contents. Publication must be a manual GitHub Actions operation from a verified
commit and use an environment-protected npm credential or trusted publishing.

## CI and stabilization

Run frozen clean install, lint, strict typecheck, unit tests, packed consumers,
  distribution/release audits, Chromium tests, build, and the dependency advisory
audit in CI. Retain the 0.5 bundle guards and lifecycle stress test; strengthen
their evidence only where a concrete gap is found.

## Operations and documentation

Document release prerequisites, versioning, dry-run, publication order,
post-publication npm/CDN verification, failed-release handling, deprecation,
and 0.5.x patch policy. Make clear that 0.x compatibility is deliberate but not
a 1.0 guarantee.

## Owner-controlled stop conditions

Do not choose a software license for the owner. Do not publish packages, create
tags/releases, or push release workflow changes using an unverified identity.
If no approved license or npm authorization is available, complete all safe
local/CI preparation and report the remaining external blocker without
claiming the public release is complete.

## Explicitly deferred

Do not add framework wrappers, new editor features, collaboration, uploads,
advanced widgets, or other Post-0.5 candidates. Stabilization may fix verified
defects but must not redesign the Phase 1–15 architecture.

## Definition of Done

- package metadata, CI, release workflow, dry-run, security and quality gates
  pass;
- Critical = 0 and High = 0;
- an owner-approved license is committed;
- real npm packages and CDN assets are verified from a clean external consumer.
